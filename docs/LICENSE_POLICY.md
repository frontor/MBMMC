
## Future license changes

A copyright holder may release a future MBMMC version under different terms for
code that the holder owns or has authority to relicense.

Changing the license later does not erase the terms already granted for copies of
an earlier release. Each published Git tag and archived release should therefore
retain the license that applied when that release was distributed.

Examples:

```text
Release 1.0.0 -> PolyForm Noncommercial 1.0.0
Release 2.0.0 -> another license chosen later
```

A user who obtained release 1.0.0 continues to rely on the license distributed with
release 1.0.0. The new license governs only the versions explicitly released under it,
unless all relevant parties separately agree otherwise.

## Contributions

Relicensing becomes more difficult when external contributors own copyright in their
contributions. Before accepting substantial external code, choose one of these
governance approaches:

1. require written permission from every copyright holder before relicensing;
2. use a contributor license agreement that expressly permits future relicensing;
3. accept contributions only when the project is willing to keep them under the
   current license;
4. keep third-party code clearly separated under its own compatible terms.

Do not assume that a GitHub pull request automatically gives the project unrestricted
future relicensing rights.

## Commercial requests

The public license does not grant commercial rights. Any commercial permission would
require a separate written agreement from the copyright holder. The public repository
does not promise that such permission will be available.

## Clinical use

Commercial restrictions and clinical-safety restrictions are different issues.
`MODEL_CARD.md` states that MBMMC is research-use-only and is not a standalone
diagnostic system. That statement does not replace the software license.
